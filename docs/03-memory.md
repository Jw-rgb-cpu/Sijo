# 3. 컴파일 타임 메모리 추론

목표: **GC 없음, 수동 해제 없음, 런타임 참조 카운팅도 거의 없음.** 할당 위치와 해제 시점을 컴파일러가 정적으로 결정합니다.

## 3.1 메모리의 4가지 영역(region)

Tofte–Talpin 영역 추론(MLKit)은 영역을 일반화된 스택으로 다룹니다. 게임은 구조가 훨씬 단순합니다 — 거의 모든 데이터의 수명이 다음 넷 중 하나입니다.

| 영역 | 수명 | 할당 비용 | 해제 비용 | 대상 |
|---|---|---|---|---|
| **Stack** | 함수 호출 | 0 | 0 | struct, 크기가 정적인 임시값 |
| **Frame** | 한 틱 | 포인터 증가(bump) | 0 (틱 끝에 일괄 리셋) | 시스템 안에서 만들고 버리는 리스트 |
| **Entity** | 엔티티 수명 | malloc 1회 | 파괴 시 자동 | 엔티티 필드에 저장되는 리스트 |
| **World** | 프로그램 수명 | 1회 | 종료 시 | 아키타입 테이블, 상수 |

## 3.2 탈출 분석 → 영역 배치

각 할당 지점(`new List<T>()`, `.Clone()`)에 대해 컴파일러는 그 값이 **어디까지 흘러가는지**를 계산합니다.

```
할당 지점 → 지역 변수 → (이동) → 다른 지역 변수 → ...
                       ↘ 엔티티 필드에 저장?   → Entity 영역
                       ↘ 함수에서 반환?        → 호출자가 영역을 결정 (영역 다형성)
                       ↘ 어디에도 탈출 안 함   → Frame 영역 (또는 Stack)
```

- 이동으로 연결된 지역 변수들을 union-find로 묶어 하나라도 탈출하면 전체를 탈출로 봅니다 (흐름 비민감, 보수적, 건전).
- **영역 다형성**: 리스트를 반환하는 함수는 숨은 할당자 매개변수를 받습니다. 호출자의 결과가 탈출하지 않으면 Frame 할당자를, 탈출하면 Heap 할당자를 넘깁니다. 같은 함수가 호출 지점에 따라 다른 영역에 할당합니다.
- 함수 인자는 기본이 빌림이므로 탈출이 아닙니다. `own` 매개변수로 넘기는 리스트는 받은 함수가 필드에 담을 수 있으므로 탈출로 보고 Heap에 할당합니다.

## 3.3 해제 시점 결정

- Frame 영역: 해제 코드 없음. 틱 끝에서 아레나 포인터 리셋 (스레드별 아레나). 그 전에도 **되감기**로 메모리를 돌려받습니다(3.3.1).
- Entity 영역: 엔티티 파괴 시 + 필드 덮어쓰기 시 이전 값 해제를 컴파일러가 삽입.
- 이동된 값: 해제하지 않음 (소유권이 넘어감). 이동은 "버퍼를 훔치고 원본을 빈 리스트로 남기는" 연산이라, 조건부 이동이 있어도 런타임 drop 플래그가 필요 없고 이동된 변수를 잘못 써도 메모리는 안전합니다(컴파일러는 그런 코드를 E0501로 거부).
- 힙 지역값은 함수의 모든 종료 지점(`return` 포함)에서 해제 코드가 자동 삽입됩니다. Mojo식 ASAP(마지막 사용 직후) 해제는 계획 단계입니다.

### 3.3.1 프레임 아레나 되감기

한 틱 안에서 임시 리스트·문자열을 많이 만드는 계산(수천 번 도는 루프, 엔티티마다 문자열 조립)은 틱 끝까지 기다리면 아레나가 계속 커집니다. 컴파일러는 아레나의 현재 위치를 표시해 두었다가 되돌려도 되는 곳을 찾아 되감기 코드를 넣습니다.

- **루프 반복마다**: 한 반복에서 할당한 것이 다음 반복에 닿을 수 없으면(바깥에 선언된 변수에 문자열·리스트를 담지 않음, 엔티티 필드·메시지·생성되는 엔티티로 보내지 않음, 바깥 컬렉션이 자라지 않음, 안에서 문자열·리스트를 반환하지 않음, await 없음, `atomic` 블록의 실행 취소 로그가 바깥 컬렉션을 그 반복 안에서 복사하지 않음 — 6.2절) 반복을 시작할 때와 루프가 끝날 때 표시 위치로 되돌립니다.
- **엔티티마다**: 엔티티 시스템이 엔티티 하나를 처리하며 할당한 것이 시스템 밖으로 나가지 않으면(위 조건을 효과 분석으로 확인), 엔티티마다 되감습니다. 그래서 엔티티 수와 무관하게 아레나 최대 사용량은 엔티티 하나 분량입니다.
- 할당하지 않는 루프에는 아무것도 넣지 않습니다. 실행 요약의 `frame arena peak`가 최대 사용량입니다.

## 3.4 용량 추론 (재할당 제거)

리스트가 루프 안에서 채워지는 패턴을 인식하여 미리 용량을 예약합니다.

```csharp
mut var near = new List<Ship>();
foreach (var s in Query<Ship>())        // 반복 횟수 상한 = Count<Ship>()
{
    if ((s.Pos - Pos).LengthSq < 100)
    {
        near.Add(s);                    // 조건부 Add라도 Frame 영역이면 상한만큼 예약하는 게 이득
    }
}
```

→ 생성 코드: `near = list_new_frame(arena, sizeof(Handle), count_Ship(w));` — 재할당 0회. Frame 아레나에선 과예약이 사실상 공짜이므로(틱 끝에 리셋) 상한 예약이 항상 이득입니다.

| 패턴 | 추론되는 용량 |
|---|---|
| `for (int i = a; i < b; i++) { xs.Add(..) }` (상수 a, b) | `b - a` |
| `foreach (var e in Query<T>()) { ... xs.Add(..) ... }` | `Count<T>()` (상한) |
| 그 외 | 기본 8, 2배 증가 |

## 3.5 엔티티 저장소

- 아키타입별 SoA 테이블: 컴포넌트 배열마다 연속 메모리, 64바이트 정렬, 2배 증가.
- 파괴는 swap-remove (O(1)), 엔티티 테이블이 `index → (archetype, row, generation)`을 관리.
- 해저드 컴포넌트(4장)만 이전 값 버퍼를 추가로 가짐.

## 3.6 무할당 문자열 포맷팅

`Print($"hp={Hp}")`처럼 보간 문자열이 즉시 소비되는 경우, 문자열 객체를 만들지 않고 `printf("hp=%d\n", hp)`로 직접 낮춥니다.

## 3.7 제약

- 리스트·배열은 다른 리스트·배열을 원소로 가질 수 있습니다(`List<List<int>>`, `int[][]`). 바깥 컬렉션이 안쪽을 소유하므로 해제·복제·이동이 재귀적으로 일어나고, 안쪽 원소는 바깥 컬렉션의 것이라 꺼내서 다른 곳에 담으면 이동이 아니라 오류입니다(E0502): `var row = grid[0].Clone();`처럼 복사하거나, `grid[0]`을 그 자리에서 씁니다. 사전의 값과 리스트의 원소로 사전은 둘 수 없습니다.
- struct 필드에 리스트·사전 불가 (struct는 POD). 문자열은 struct에 둘 수 있음(3.8절).
- 메모리 관련 결정은 모두 `sijoc explain`의 `[memory]` 절에 할당 지점별로 출력됩니다.

## 3.8 문자열: 프레임 아레나 + 틱 경계 수집기

문자열은 불변 값 `{포인터, 바이트 길이, 종류}`입니다(종류: 정적/힙/프레임). 수명 주석도, 참조 카운트도, 대입 시 복사도 없이 안전하게 만드는 방법은 다음과 같습니다.

1. **임시 문자열은 프레임 아레나에 할당합니다.** 연결, 보간, `Substring`, `ToString` 등 실행 중 만들어지는 모든 문자열은 스레드별 프레임 아레나에 bump 할당되므로, 병렬 시스템 안에서도 `malloc`도 잠금도 없습니다. 리터럴은 정적 데이터를 가리킵니다.
2. **틱이 끝날 때 살아남은 문자열만 옮깁니다.** 컴파일러는 게임 상태의 모든 문자열 칸(필드, struct 멤버, 리스트 원소, 사전 키·값)을 타입에서 알기 때문에, **정확한 루트 방문 함수**를 생성합니다. 프레임 아레나를 비우기 직전에 이 함수가:
   - 상태가 아직 참조하는 프레임 문자열을 문자열 힙으로 옮기고(같은 문자열을 여러 칸이 참조하면 한 번만 복사) 칸을 고쳐 쓰며,
   - 참조되는 힙 문자열에 표시하고, 표시되지 않은 힙 문자열을 해제합니다.
3. **왜 안전한가:** 수집은 틱 사이에만 일어나고, 그때는 지역 변수가 하나도 살아 있지 않습니다. 그래서 스택 맵도 쓰기 장벽도 필요 없고, 틱 도중 지역 변수가 가리키는 문자열(다른 엔티티의 필드에서 읽은 값 포함)은 그 틱이 끝날 때까지 절대 해제되지 않습니다. 해저드 스냅샷, `atomic` 실행 취소 로그, 지연 명령에 담긴 문자열도 같은 이유로 유효합니다.
4. **비용:** 대입은 포인터 복사입니다. 수집 비용은 문자열 칸 수와 힙 문자열 수에 비례합니다(이 칸만 순회하므로 문자열이 없는 프로그램은 0). 실행 요약에 `strings: N live on the heap (… bytes), P promoted, F freed`가 나옵니다.

검증: `tests/programs/strings.sijo`가 ASan/UBSan, 스레드 1/4 동일 체크섬, 150+150틱 저장·복원 = 300틱 연속 실행을 확인합니다. 저장 파일에는 문자열이 값(16진 바이트)으로 기록됩니다.
